KhiCAS mapped RC1 — fx-9860GIII 实机候选
2026-11-16

这是包含真实 CAS、原有 UI 和绘图的完整接入候选，不是显示数字的 probe。
已经通过本项目隔离模拟器测试；你的 fx-9860GIII / OS 03.70.0200 仍待实测。

一、安装

1. 先保存计算器中正在编辑的内容。
2. 从本包仅复制两个文件到计算器存储根目录：
   KhiMap.g1a   9,880 字节
   KHICAS.BIN   2,859,236 字节
   合计 2,869,116 字节，另需少量文件系统余量。
3. 两文件必须来自同一包，不要给 BIN 改名、截断或改成 g1a。
   TXT、JSON 和校验文件无需复制到计算器。
4. 从系统菜单打开 KhiMap。先出现 Checking KHICAS.BIN，
   随后 Starting CAS。第一次请给完整性扫描约一分钟等待时间；
   这是观察建议，不是已测得的实机启动时长。
5. 进入后的标题仍显示 KhiCAS BASE02，布局沿用你之前认可的版本。

二、优先测试这四项

1. simplify(2x+x)         应得到 3*x
2. solve(2x=10,x)        应得到 [5]，界面可能写成 list[5]
3. integrate(sin(x),x)   应得到 -cos(x)
4. plot(x^2,x)           应显示抛物线；方向键平移、+/- 缩放、EXE 复位。

AC 清空输入，F1 为代数，F2 为微积分，F4 打开目录；目录中左右切页。
在图形界面按 EXIT 回到输入界面，再按 EXIT 返回系统菜单。
请测试“退出 → 直接再进”3次；重新进入会创建空会话，不保留上次变量。
MENU 也会先清理再返回系统。关机/再开机在模拟器中不能完整验证，
建议先完成上述基本测试，再测试 SHIFT+AC 的关机路径。

三、上述正常后，可追加检查

diff(x^3,x)                  3*x^2
limit(sin(x)/x,x,0)          1
det([[1,2],[3,4]])           -2

内存恢复检查（属于压力测试，不是正常算例）：
先输入 x:=7，再输入 expand((y+1)^1000)。
模拟器中后者会提示 Memory limit; variables preserved。
随后输入 x+1，应仍得到8；再次进入图形/退出程序应正常。
不要把被预算拒绝的大表达式当成完整桌面 Giac 的运算能力。

四、错误反馈

若启动失败，请拍下 Error / Stage / Status 三行。
Error 是十六进制：
0000000A  找不到 KHICAS.BIN
0000000B  文件长度不匹配
0000000C  物理页查询失败或返回地址不符合检查条件
0000000D  关闭文件失败
0000000E  完整性校验不匹配，请重新复制本包两个文件
00000014  启动器内存分配失败（也可能直接显示 Not enough memory）
0000001F  可用映射槽不足
00000028  CAS 启动失败；Stage5/Status6 表示32KiB计算区申请失败
00000065 起的一组数值  OS映射例程指纹未通过（不要绕过检查）

若长时间停在 Starting CAS、显示系统错误或无法返回，请记录画面和
最后一次输入；必要时使用 RESET 恢复。部分底层初始化失败仍采用
停住策略，以免继续破坏未知的系统状态。这不是已经认证稳定的正式版。

五、这一版解决了什么

大程序留在 Flash 的 BIN 中按需映射，小 g1a 负责 OS 识别。
它没有把2.86MB整个复制进RAM，也没有去压缩/砍掉 C++异常处理。
Release启动器与页表等占6,912B堆，CAS固定区32,768B。
本轮保留现有计算器数学内核和界面，没有嵌入Python。
为优先验证正确性，首版外部Flash执行不使用缓存，速度可能偏慢。
目前优势是能继续保留数学基础并避开单个大g1a的装载路线；
不声称已比原版更快或经实机证明更稳定。
