## 2. 数学核心的来源与 formal 恢复

采用已完成符号事务、求解器生命周期和相关内存修复的完整 static 归档：

```text
/root/khicas-work/symbol-transaction-20261114/combined-clean-static/libgiac.a
SHA-256 1b127e8f3e44cdb7452ea5d8bad8e792d1a6ea4bfa6962a14910d2598028e098
```

原 UI 候选位于 `audit/symbol-transaction-ui-size-20261114/inputs`，其中 formal 归档 SHA-256 为 `7a534b98ec82061a1ad252d7610ce6de0c3247194f929ea8be9750339bd14614`。对两份归档的全部 39 个成员逐字比较，唯一差异为 `kderive.o`；其余 38 个数学对象完全相同。

formal 版本把一个二参数形式求导叶移到外部模块，未绑定时会报 `Formal derivative leaf unavailable`。本次改用完整 static 归档，恢复原数学分支，移除那一套 23-import roots、binder 和 FORMAL.LIB 依赖。没有通过删去数学函数降低体积，也不需要独立 8 KiB formal 模块窗口。

| 相同 UI / 32 KiB arena / 24 KiB 计费上限 | ROM span 加 512 B |
| --- | ---: |
| 原 clean47cd formal 候选 | 2,857,444 B |
| 本次完整 static 控制链接 | 2,858,556 B |
| 恢复完整数学的净增量 | **1,112 B** |

归档中的 `kderive.o` 文件长度差为 2,208 B，不能把它当作最终 ROM 差值；LTO 后实际净增量为上表的 1,112 B。

核查文件为 `audit/mapped-integration-20261116/build-review/{REVIEW.md,resident-formal-restoration.json,static-ui-link.json,build-review-evidence.tar.gz}`。完整核心仍是当前保留的计算器数学配置，不代表桌面 Giac 的全部功能；之前尚未完成的 Lambert W、新几何、完整 3D、交互输入适配不由此恢复自动补齐。

本次复建范围是：从冻结归档重链接全部真实 CAS，重新编译映射运行时的小型接线文件。39 个数学单元未在本轮重新从上游源包编译。需要重建数学归档时，应另按 `tools/prepare_legacy_giac.py`、`tools/probe_legacy_giac.py` 和工程手册核对生成清单、配置及所有运行库，不能把旧 VM 项目副本当作当前 Windows 源的权威副本。

## 3. Payload 输入与替换对象

本次映射运行时的七个源文件均在 `integrations/mapped-cas-20261116/payload/`：

| 文件 | 用途 |
| --- | --- |
| `start.c` | 保留32 KiB启动、帧和构造流程；入口第三参数接收常驻 API；提前建立异常退出边界 |
| `main.c` | 沿用现有真实 CAS / 绘图 UI；MENU/OFF/EXIT 清理后交回启动器 |
| `binding.c` | API绑定、stage记录、URAM refill/syscall槽和跨world的IMASK处理 |
| `atomic.c` | 保留gint atomic API，修正loader shim与gint切换时的中断屏蔽恢复 |
| `map_api.h` | 28 B SH32 API、阶段和退出原因的明确接口 |
| `tlbh.S` | 128 B TLB handler，经URAM槽调用常驻refill，边界取linker符号 |
| `syscalls.S` | 经常驻gateway调用OS，避免在异常映射中使用原ROM thunk |

保留原候选输入 `01–07`、`10–12`、`14–15`、`17–19`；替换 `00-main.o`、`09-gint_start32.o` 和链接脚本，并增加 `binding.o`。数学归档换成上述完整 static 版本。原 gint 归档复制到隔离输出后，删除 `start.c.obj`、`tlbh.S.obj`、`syscalls.S.obj`、`atomic.c.obj`；安装新的后三个成员，启动对象直接参加链接，防止旧入口或旧实现被再次拉入。

保留受控 TomMath、异常版 libstdc++、私有 FDE、帧注册和 bootstrap 的冻结内容。物理应用池为 32,768 B，数学跟踪上限为 24,576 B；启动器常驻块另占 OS 堆，不能从池内再扣出或重复相加。

构建脚本：

```text
integrations/mapped-cas-20261116/tools/build_payload.py
```

脚本默认只生成计划；`--compile-only` 只编译小型替换对象；`--run` 执行一次串行 `-flto=1 -Oz -fno-ipa-cp` 完整链接。每次绑定源文件、头文件、编译器、冻结库、对象和生成脚本的 SHA-256，并在链接前后复查；没有未定义符号、没有 formal 缺库路径后才生成成功报告。

## 8. 验证证据与收尾

完整新 ELF 无未定义符号，无formal缺库路径；未剥离ELF的Python入口/运行时扫描通过。Debug/Release构建和resident闭合核查通过。带固件的HLE模拟已有真实代数、求导、积分、极限与绘图路径执行记录；持续回归的最新结果见 `evidence/` 中各会话输入和结果，不在本文预先宣布尚未完成的测试成功。

独立启动拒绝测试脚本为 `tools/test_loader_rejections.py`。`evidence/loader-rejections-debug/` 覆盖缺BIN、错误长度、4096 B堆不能分配启动器；`evidence/loader-rejections-extended-debug/` 覆盖32768 B堆能分配启动器但CAS32申请失败，以及同长度BIN中点仅翻1 B的SHA拒绝。每例均保留输入哈希、小型syscall摘要和实际屏幕，未写目标寄存器或内存，未改bundle。扩展两例各实际执行约45.5 s的全文件SHA；CAS OOM显示Error28/Stage5/Status6，SHA损坏显示Error0E/Stage0/Status0，之后释放启动器Context并等待OS GetKey。CAS路径的模型状态保留已处理TLB fault历史，未将其篡改为空error。

这些是电脑侧和模型证据。外部Flash实际寻址、真实OS生命周期及用户设备长期稳定性，仍需要使用本次绑定文件进行设备验收。
